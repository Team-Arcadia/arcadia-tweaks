# Changelog

All notable changes to ArcadiaTweaks are documented here.

---

## [0.3.0] - 2026-11-05

### Performance

- **Refined Storage: autocrafting calculations no longer copy the whole network (A1)** — `CraftingState.of` copies every resource of the network before each autocrafting calculation, and Refined Storage runs at least two calculations (one more per extra pattern of the item) each time an exporter, interface or constructor with an autocrafting upgrade asks for an item it cannot find and cannot craft, on every work cycle and for every filter. On a network of thousands of resources that copy was most of the cost. Calculations that run on the server thread now read the network directly through a read-only view; nothing can change the network while they run, so the results are the same. Crafting previews, which run on Refined Storage's own threads, keep the copy. Bench `refinedstorage_autocraft` (16 exporters with 3 speed upgrades and an autocrafting upgrade, 9 missing patterned filters each, 3549 resources): 22.7 ms to 0.29 ms per tick. A differential GameTest compares 3600 task plans, previews and craftable amounts over 5 random pattern graphs (alternatives, byproducts, cycles): all equal with A1 off and on. Kill switch `[refinedstorage] autocrafting_live_storage_view_enabled`.
- **Refined Storage: idle importers, exporters and refused crafting steps try less often (B1 to B3)** — an importer, an exporter or a processing step of a running autocrafting task whose attempts move nothing (empty source, full destination, missing item, busy or locked machine) tried again on every work cycle, which is every tick with speed upgrades, and each attempt simulates extractions and insertions through the network and the neighbouring inventory. Such a node now waits 2 ticks, then 4, 8... up to `idle_backoff_max_ticks` (10 by default, a little less per node so idle nodes do not all retry on the same tick), and is back to every cycle at the first transfer. It is still tried at least once per maximum, its energy use is unchanged, and any change of filters, upgrades, facing or network brings it back to every cycle. A node whose own cycle is already that slow (no speed upgrades) is never slowed down. Bench `refinedstorage_idle_io` (24 exporters with missing filters, 24 exporters into full chests, 24 importers on empty chests, 12 tasks waiting for a full machine, 4 speed upgrades each): 5.06 ms to 0.72 ms per tick (p95 7.3 ms to 2.7 ms), same results; the busy bench loop moves the same 460 items per phase with and without. GameTests: after an idle period the first item moves within 10 ticks (1 tick in plain Refined Storage), and the backoff is engaged beforehand. Kill switches `[refinedstorage] importer_idle_backoff_enabled`, `exporter_idle_backoff_enabled`, `autocrafting_sink_backoff_enabled`.

### Other changes

- With every 0.3.0 patch, the `refinedstorage_autocraft` bench goes from 20.9 ms to 0.16 ms per tick.
- New admin menu row "Refined Storage IO" with B1 to B3 and the maximum.
- The startup log now says whether A1 and B1 to B3 are applied (`patches applied: A1=true ...`): their target classes are loaded at server start, so a patch that no longer fits a Refined Storage version shows at once instead of the first time a node uses it.
- Bench: two new scenarios (`refinedstorage_autocraft`, `refinedstorage_idle_io`), each filter's last result recorded per phase, and `-PbenchJfr=<file.jfr>` records a Java Flight Recorder profile of a run.
- This release also carries the 0.2.2 client crash fixes, which were handed out as a jar but never published.

### Performances

- **Refined Storage : les calculs d'autocrafting ne copient plus tout le réseau (A1)** — `CraftingState.of` copie chaque ressource du réseau avant chaque calcul d'autocrafting, et Refined Storage lance au moins deux calculs (un de plus par pattern supplémentaire de l'objet) chaque fois qu'un exporter, une interface ou un constructeur avec upgrade d'autocrafting demande un objet qu'il ne trouve pas et ne peut pas crafter, à chaque cycle de travail et pour chaque filtre. Sur un réseau de milliers d'objets, cette copie faisait l'essentiel du coût. Les calculs qui tournent sur le thread serveur lisent maintenant le réseau directement, par une vue en lecture seule ; rien ne peut modifier le réseau pendant qu'ils tournent, les résultats sont donc les mêmes. Les aperçus de craft, calculés sur les threads de Refined Storage, gardent la copie. Banc `refinedstorage_autocraft` (16 exporters avec 3 upgrades de vitesse et une upgrade d'autocrafting, 9 filtres à pattern manquants chacun, 3549 ressources) : 22,7 ms à 0,29 ms par tick. Un GameTest différentiel compare 3600 plans de tâche, aperçus et quantités craftables sur 5 graphes de patterns aléatoires (alternatives, sous-produits, cycles) : tous égaux avec A1 coupé ou actif. Interrupteur `[refinedstorage] autocrafting_live_storage_view_enabled`.
- **Refined Storage : les importers, exporters et étapes de craft refusées inactifs réessaient moins souvent (B1 à B3)** — un importer, un exporter ou une étape de traitement d'une tâche d'autocrafting en cours dont les essais ne déplacent rien (source vide, destination pleine, objet absent, machine occupée ou verrouillée) réessayait à chaque cycle de travail, donc à chaque tick avec des upgrades de vitesse, et chaque essai simule des extractions et insertions dans le réseau et l'inventaire voisin. Un tel nœud attend maintenant 2 ticks, puis 4, 8... jusqu'à `idle_backoff_max_ticks` (10 par défaut, un peu moins selon le nœud pour que les nœuds inactifs ne réessaient pas tous au même tick), et revient à chaque cycle au premier transfert. Il est quand même essayé au moins une fois par maximum, sa consommation d'énergie ne change pas, et tout changement de filtres, d'upgrades, d'orientation ou de réseau le ramène à chaque cycle. Un nœud dont le cycle est déjà aussi lent (sans upgrade de vitesse) n'est jamais ralenti. Banc `refinedstorage_idle_io` (24 exporters à filtres manquants, 24 exporters vers des coffres pleins, 24 importers sur des coffres vides, 12 tâches qui attendent une machine pleine, 4 upgrades de vitesse chacun) : 5,06 ms à 0,72 ms par tick (p95 7,3 ms à 2,7 ms), mêmes résultats ; la boucle active du banc déplace les mêmes 460 objets par phase avec et sans. GameTests : après une période d'attente, le premier objet bouge en moins de 10 ticks (1 tick dans Refined Storage normal), et le ralentissement est bien engagé avant. Interrupteurs `[refinedstorage] importer_idle_backoff_enabled`, `exporter_idle_backoff_enabled`, `autocrafting_sink_backoff_enabled`.

### Autres changements

- Avec tous les patchs de la 0.3.0, le banc `refinedstorage_autocraft` passe de 20,9 ms à 0,16 ms par tick.
- Nouvelle ligne « Refined Storage IO » dans le menu d'administration, avec B1 à B3 et le maximum.
- Le log de démarrage indique maintenant si A1 et B1 à B3 sont appliqués (`patches applied: A1=true ...`) : leurs classes cibles sont chargées au démarrage du serveur, donc un patch qui ne correspond plus à une version de Refined Storage se voit tout de suite, et pas la première fois qu'un nœud l'utilise.
- Banc : deux nouveaux scénarios (`refinedstorage_autocraft`, `refinedstorage_idle_io`), le dernier résultat de chaque filtre relevé à chaque phase, et `-PbenchJfr=<fichier.jfr>` enregistre un profil Java Flight Recorder d'une exécution.
- Cette version contient aussi les correctifs de crash client de la 0.2.2, distribuée en jar mais jamais publiée.

## [0.2.2] - 2026-11-03

### Fixed

- **Copycats+: client crash while building chunk meshes** — `MultiStateCopycatBlockEntity.invalidate()` empties the copycat's material storage, and Create calls it from `setRemoved()`, which runs whenever a chunk is unloaded or resent by the server. Sodium builds chunk meshes on worker threads from a copy of the section that keeps the same block entity objects, so a mesh task started just before the removal still reads that copycat; with its storage empty, `getMaterialItem(property)` returned null and `IMultiStateCopycatBlockEntity.isCTEnabled()` threw a `NullPointerException` ("Encountered exception while building chunk meshes", `copycats:copycat_slab`, two client crashes on 2026-11-02). The storage is now kept on removal; the chunk drops the block entity anyway. New module `copycats`, applied only when Copycats+ is installed and its `invalidate()` still clears the storage. Kill switch `[safety] copycatsKeepMaterialsOnRemove`.
- **Client: block entity maps of client chunks changed from another thread** — on a client, `Level.getBlockEntity` has no thread check (the server returns null to other threads), so a call from any thread reaches `LevelChunk.getBlockEntity` with `IMMEDIATE` creation and can remove, promote or create a block entity in the chunk's maps, which are not thread-safe. When that happened while the render thread did the same (Sodium cloning a section, NeoForge refreshing model data), the client crashed with a `ConcurrentModificationException` in `LevelChunk.updateBlockEntityTicker` or an `ArrayIndexOutOfBoundsException` in `Object2ObjectOpenHashMap.rehash` (four client crashes on 2026-11-03). For a chunk the client level holds, a call from another thread now only reads what is already in the map, and `setBlockEntity` / `removeBlockEntity` from another thread run on the render thread. The mod making those calls could not be identified from the crash reports, which only show the render thread; the first five calls are logged with their stack trace so it can be found. Kill switch `[safety] clientBlockEntityThreadGuard`, read from each player's own config.

### Correctifs

- **Copycats+ : crash du client pendant la construction des meshes de chunks** — `MultiStateCopycatBlockEntity.invalidate()` vide le stockage des matériaux du copycat, et Create l'appelle depuis `setRemoved()`, qui s'exécute dès qu'un chunk est déchargé ou renvoyé par le serveur. Sodium construit les meshes de chunks sur des threads de travail à partir d'une copie de la section qui garde les mêmes objets block entity : une tâche de mesh lancée juste avant le retrait lit donc encore ce copycat ; avec un stockage vide, `getMaterialItem(property)` renvoyait null et `IMultiStateCopycatBlockEntity.isCTEnabled()` levait une `NullPointerException` (« Encountered exception while building chunk meshes », `copycats:copycat_slab`, deux crashs client le 2026-11-02). Le stockage est maintenant conservé au retrait ; le chunk abandonne le block entity de toute façon. Nouveau module `copycats`, appliqué seulement si Copycats+ est installé et que son `invalidate()` vide toujours le stockage. Interrupteur `[safety] copycatsKeepMaterialsOnRemove`.
- **Client : tables de block entities des chunks client modifiées depuis un autre thread** — côté client, `Level.getBlockEntity` ne vérifie pas le thread (le serveur renvoie null aux autres threads) : un appel depuis n'importe quel thread arrive dans `LevelChunk.getBlockEntity` en création `IMMEDIATE` et peut retirer, promouvoir ou créer un block entity dans les tables du chunk, qui ne sont pas thread-safe. Quand cela arrivait pendant que le thread de rendu faisait de même (Sodium qui copie une section, NeoForge qui rafraîchit les model data), le client crashait avec une `ConcurrentModificationException` dans `LevelChunk.updateBlockEntityTicker` ou une `ArrayIndexOutOfBoundsException` dans `Object2ObjectOpenHashMap.rehash` (quatre crashs client le 2026-11-03). Pour un chunk que le monde client possède, un appel depuis un autre thread ne fait plus que lire ce qui est déjà dans la table, et `setBlockEntity` / `removeBlockEntity` depuis un autre thread s'exécutent sur le thread de rendu. Le mod à l'origine de ces appels n'a pas pu être identifié depuis les rapports de crash, qui ne montrent que le thread de rendu ; les cinq premiers appels sont journalisés avec leur pile d'appels pour le retrouver. Interrupteur `[safety] clientBlockEntityThreadGuard`, lu dans la config de chaque joueur.

## [0.2.1] - 2026-11-01

### Fixed

- **Simply Swords: server crash in the gloam stain purge (Arcadia bug #328)** — `GloamStainManager.purgeOrphans` walks every entity of the level and discarded orphan gloam stain visuals during that walk. Each discard removes the entity from the level's entity index, the map the walk is reading; once enough entities go, the map shrinks and the walk reads past its table (`ArrayIndexOutOfBoundsException` in `Int2ObjectLinkedOpenHashMap`) and the server crashes. Server1 crashed this way when a player was teleported into a dungeon: their chunks stayed loaded but stopped ticking, so their stains outlived their own tick and the purge removed them all at once. The stains are now collected during the walk and discarded right after it, in the same tick. Reproduced on a test server with 400 orphan stains (crash with 0.2.0, all 400 removed and no crash with 0.2.1). Kill switch `[safety] gloamStainPurgeDeferredDiscard`.

### Correctifs

- **Simply Swords : crash du serveur pendant la purge des taches de Gloam (bug Arcadia #328)** — `GloamStainManager.purgeOrphans` parcourt toutes les entités du monde et supprimait les visuels de taches de Gloam orphelins pendant ce parcours. Chaque suppression retire l'entité de l'index des entités du monde, la table que le parcours est en train de lire ; une fois assez d'entités retirées, la table rétrécit, le parcours lit au-delà (`ArrayIndexOutOfBoundsException` dans `Int2ObjectLinkedOpenHashMap`) et le serveur crashe. Server1 a crashé ainsi quand un joueur a été téléporté dans un donjon : ses chunks restaient chargés mais ne tournaient plus, ses taches survivaient donc à leur propre tick et la purge les retirait toutes d'un coup. Les taches sont maintenant relevées pendant le parcours et supprimées juste après, dans le même tick. Reproduit sur un serveur de test avec 400 taches orphelines (crash en 0.2.0, les 400 retirées sans crash en 0.2.1). Interrupteur `[safety] gloamStainPurgeDeferredDiscard`.

## [0.2.0] - 2026-10-26

### Fixed

- **Refined Storage: activeness changes applied up to 19 s late** — The S1 activeness coalescing only called `updateActiveness` every 20 ticks, but Refined Storage 2.0.9 debounces changes with a counter that only moves on calls, so every change after the first one (power back, redstone mode switched) waited up to about 380 ticks instead of 19 before importers and exporters reacted. The counter now advances by the ticks that were skipped, so a change lands at most `interval - 1` ticks away from plain Refined Storage. Measured in a GameTest: delays of 6 to 20 ticks with the fix, 386 ticks before it.
- **Simply Swords: no more free Runic Tablets (Arcadia bug #321)** — A unique weapon without the `simplyswords:awakening` component (weapons from before the awakening system, or handed out as a plain item by lootboxes, quests and commands) counts as level 8, and the Runic Forge turned those 8 implicit levels into 8 real Runic Tablets. The implicit level is now stored on the weapon as a lock the first time it enters the forge: the forge gives no tablet for it, the weapon keeps its power, its gems can still be changed, and the tablet slots covered by the lock refuse tablets. Weapons awakened with real tablets are untouched. Kill switch `[safety] runicForgeImplicitLevelLock`.
- **Waystones: "Visible to Team" follows FTB Teams** — Waystones resolved TEAM visibility from the vanilla scoreboard team, which the Arcadia tab list uses to sort players by rank, so every player of the same rank saw everyone else's team waystones. A TEAM waystone is now offered only to its owner and to the owner's FTB Teams party (allies excluded, fail closed while FTB Teams is not loaded). Kill switches `[modules] waystones` and `[waystones] team_visibility_uses_ftb_teams`.
- **Server freeze from runaway entity movement** — An entity whose velocity grew to absurd values (seen on Aether mobs, up to 1e20 blocks per tick) made `Entity.move` walk millions of blocks in the collision search and the watchdog killed the server. A movement that is NaN, infinite or above the limit on one axis now resets the entity's velocity and skips the move, with one rate-limited warning. Dedicated servers only, kill switch `[safety] entityMoveGuard`, limit `entityMoveGuardLimit` (100 blocks per tick).
- **The BotanyPots module switch did nothing** — `[modules] botany = false` left every BotanyPots strategy running. Each strategy now also requires the module switch, like the other modules.

### Performance

- **CosmeticWeapons and CosmeticArmours: item presence gate** — The 15 advancement procedures that test several items every player tick called `Inventory.contains` once per item, and every call scanned the inventory, Curios and Accessories. After the first lookup of a call, items that are not in the inventory are now answered without a new scan. Same answers and same advancements (822 placements, near misses and 500 random inventories compared with the gate on and off). Bench: 434 to 100 microseconds per player tick for the 26 procedures. A startup audit turns the gate off if an unknown Mixin hooks `Inventory.contains` or the ItemStack comparison. New module `cosmetic`, switch `[cosmetic] contains_presence_gate`.
- **Accessories: `contains` fast path and lighter entity tick** — Accessories' extension of `Inventory.contains(ItemStack)` can never match (its predicate tests `isEmpty()`), yet it scanned every accessory slot on each call; the scan is now skipped while every state-changing call is kept in order (1.6 to 0.5-0.7 microseconds per call). The per-entity Accessories tick allocates about 45% less (3976 to 2360 bytes per player tick). Both are pinned to Accessories 1.1.0-beta.54 by bytecode fingerprints and switch themselves off on any other build. New module `accessories`, switches `[accessories] contains_fast_path` and `tick_allocation_trimmed`.
- **Refined Storage: faster autosave** — Every autosave re-encoded every storage disk of the world as soon as one disk changed. Disks unchanged since the last save now reuse their encoded form (200 disks with 5% changed: 95 to 8 ms per save in the bench). Saved data is byte-identical with the cache on and off; every 20th save re-encodes and compares, and any difference turns the cache off for the session. Switches `storage_save_cache_enabled`, `storage_save_cache_verify_interval`.
- **Refined Storage: single component lookup and quieter debug log** — One hash lookup instead of two per network component access, and the "External storage has changed" and transmitter retry lines no longer flood `debug.log` from the tick loop. Switches `single_component_lookup_enabled`, `quiet_hot_debug_logs_enabled`.

### Changed

- **One published jar** — `arcadiatweaks-0.2.0.jar` carries every module; the single-module jars stay available as Gradle tasks for internal testing only.
- **Admin menu** — `/arcadia_tweaks gui` (renamed from `/arcadiatweaks gui`, `admin` stays an alias) is now a paged 9x6 menu: one row per module with its switch first, a safety guards row, the default value in every tooltip, and a two-click "Recommended defaults" reset.
- **Defaults** — Every optimization proven identical by the tests is on by default; BotanyPots A2 (light flag downgrade) stays off because it changes neighbour updates.
- **Built against the current Arcadia modpack** — Target mod versions in `gradle.properties` match the jars the modpack runs, so a plain `./gradlew build` works.
- **Cleaner logs** — The unused `refmap` entry is gone from every Mixin config (six warnings less on each start).
- **Tests** — 83 JUnit tests and 39 GameTests, including the real Runic Forge, FTB Teams parties, a Refined Storage network and its save, and Cosmetic and Accessories differential tests (patch on against patch off). A GameTest drives the admin menu with a FakePlayer.
- **Documentation** — README (English and French) lists every module, the `[safety]` section and the test commands; this changelog was added. Curveo added to the authors.

### Correctifs

- **Refined Storage : changements d'activité appliqués jusqu'à 19 s en retard** — La fusion S1 des vérifications d'activité n'appelait `updateActiveness` que toutes les 20 ticks, alors que Refined Storage 2.0.9 temporise les changements avec un compteur qui n'avance qu'à chaque appel : chaque changement après le premier (retour du courant, mode redstone modifié) attendait jusqu'à environ 380 ticks au lieu de 19 avant que les importeurs et exportateurs réagissent. Le compteur avance maintenant des ticks sautés, donc un changement arrive au plus `interval - 1` ticks de Refined Storage normal. Mesuré en GameTest : 6 à 20 ticks avec le correctif, 386 ticks avant.
- **Simply Swords : plus de Runic Tablets gratuites (bug Arcadia #321)** — Une arme unique sans le composant `simplyswords:awakening` (armes d'avant le système d'éveil, ou données comme simple objet par les lootboxes, les quêtes et les commandes) compte comme niveau 8, et la Runic Forge transformait ces 8 niveaux implicites en 8 vraies Runic Tablets. Le niveau implicite est maintenant enregistré sur l'arme comme un verrou la première fois qu'elle entre dans la forge : la forge ne donne aucune tablette pour lui, l'arme garde sa puissance, ses gemmes peuvent toujours être changées, et les emplacements couverts par le verrou refusent les tablettes. Les armes éveillées avec de vraies tablettes ne changent pas. Interrupteur `[safety] runicForgeImplicitLevelLock`.
- **Waystones : « Visible to Team » suit FTB Teams** — Waystones déterminait la visibilité TEAM à partir de l'équipe du scoreboard vanilla, que la tab list d'Arcadia utilise pour trier les joueurs par grade : tous les joueurs d'un même grade voyaient les waystones d'équipe des autres. Une waystone TEAM n'est maintenant proposée qu'à son propriétaire et à la partie FTB Teams du propriétaire (alliés exclus, rien n'est proposé tant que FTB Teams n'est pas chargé). Interrupteurs `[modules] waystones` et `[waystones] team_visibility_uses_ftb_teams`.
- **Gel du serveur par un mouvement d'entité incontrôlé** — Une entité dont la vitesse grimpait à des valeurs absurdes (vu sur des mobs de l'Aether, jusqu'à 1e20 blocs par tick) faisait parcourir des millions de blocs à `Entity.move` pendant la recherche de collisions, et le watchdog tuait le serveur. Un mouvement NaN, infini ou au-delà de la limite sur un axe remet maintenant la vitesse de l'entité à zéro et saute le déplacement, avec un avertissement limité dans le temps. Serveurs dédiés uniquement, interrupteur `[safety] entityMoveGuard`, limite `entityMoveGuardLimit` (100 blocs par tick).
- **L'interrupteur du module BotanyPots ne faisait rien** — `[modules] botany = false` laissait tourner toutes les stratégies BotanyPots. Chaque stratégie exige maintenant aussi l'interrupteur du module, comme les autres modules.

### Performance

- **CosmeticWeapons et CosmeticArmours : filtre de présence des objets** — Les 15 procédures de progrès qui testent plusieurs objets à chaque tick joueur appelaient `Inventory.contains` une fois par objet, et chaque appel parcourait l'inventaire, Curios et Accessories. Après la première recherche d'un appel, les objets absents de l'inventaire obtiennent maintenant leur réponse sans nouveau parcours. Mêmes réponses et mêmes progrès (822 placements, quasi-correspondances et 500 inventaires aléatoires comparés filtre activé et désactivé). Banc : 434 à 100 microsecondes par tick joueur pour les 26 procédures. Un audit au démarrage coupe le filtre si un Mixin inconnu modifie `Inventory.contains` ou la comparaison d'ItemStack. Nouveau module `cosmetic`, interrupteur `[cosmetic] contains_presence_gate`.
- **Accessories : raccourci de `contains` et tick d'entité allégé** — L'extension d'Accessories pour `Inventory.contains(ItemStack)` ne peut jamais correspondre (son prédicat teste `isEmpty()`), mais elle parcourait chaque emplacement d'accessoire à chaque appel ; ce parcours est maintenant sauté en gardant, dans l'ordre, chaque appel qui modifie un état (1,6 à 0,5-0,7 microseconde par appel). Le tick Accessories de chaque entité alloue environ 45 % de moins (3976 à 2360 octets par tick joueur). Les deux sont liés à Accessories 1.1.0-beta.54 par des empreintes de bytecode et se coupent seuls sur toute autre version. Nouveau module `accessories`, interrupteurs `[accessories] contains_fast_path` et `tick_allocation_trimmed`.
- **Refined Storage : sauvegarde automatique plus rapide** — Chaque sauvegarde automatique réencodait tous les disques de stockage du monde dès qu'un seul disque avait changé. Les disques inchangés depuis la dernière sauvegarde réutilisent maintenant leur forme encodée (200 disques dont 5 % modifiés : 95 à 8 ms par sauvegarde au banc). Les données sauvegardées sont identiques octet pour octet avec et sans le cache ; une sauvegarde sur 20 réencode et compare, et toute différence coupe le cache pour la session. Interrupteurs `storage_save_cache_enabled`, `storage_save_cache_verify_interval`.
- **Refined Storage : une seule recherche de composant et log debug allégé** — Une seule recherche dans la table au lieu de deux pour chaque accès à un composant du réseau, et les lignes « External storage has changed » et de nouvel essai des transmetteurs n'inondent plus `debug.log` depuis la boucle de tick. Interrupteurs `single_component_lookup_enabled`, `quiet_hot_debug_logs_enabled`.

### Modifications

- **Un seul jar publié** — `arcadiatweaks-0.2.0.jar` contient tous les modules ; les jars à module unique restent disponibles comme tâches Gradle pour les tests internes uniquement.
- **Menu d'administration** — `/arcadia_tweaks gui` (renommé depuis `/arcadiatweaks gui`, `admin` reste un alias) est maintenant un menu 9x6 en pages : une ligne par module avec son interrupteur en premier, une ligne de gardes-fous, la valeur par défaut dans chaque info-bulle, et un bouton « Réglages recommandés » à deux clics.
- **Valeurs par défaut** — Toute optimisation prouvée identique par les tests est activée par défaut ; BotanyPots A2 (rétrogradation des drapeaux de lumière) reste désactivée car elle change les mises à jour des blocs voisins.
- **Compilé contre le modpack Arcadia actuel** — Les versions des mods ciblés dans `gradle.properties` correspondent aux jars du modpack : un simple `./gradlew build` fonctionne.
- **Logs plus propres** — L'entrée `refmap` inutile a disparu de chaque config Mixin (six avertissements de moins à chaque démarrage).
- **Tests** — 83 tests JUnit et 39 GameTests, dont la vraie Runic Forge, les parties FTB Teams, un réseau Refined Storage et sa sauvegarde, et des tests comparatifs Cosmetic et Accessories (patch activé contre patch désactivé). Un GameTest manipule le menu d'administration avec un FakePlayer.
- **Documentation** — Le README (anglais et français) liste chaque module, la section `[safety]` et les commandes de test ; ce changelog a été ajouté. Curveo ajouté aux auteurs.

## [0.1.1] - 2026-05-18

### Added

- **Refined Storage module** — Coalesced network node and transmitter activeness checks.
- **Mekanism module** — Backoff for idle transmitter pull scans, network emit scans and Logistical Transporter idle path recalculations, plus an optional client-side safe rendering path for colored Logistical Transporters with a model cache guard.
- **Jar variants** — `all`, `botany`, `refinedstorage` and `mekanism`; the admin GUI command follows the selected variant.
- **Structural Mixin checks** — A changed target skips only the affected Mixin instead of crashing the whole jar.

### Ajouts

- **Module Refined Storage** — Regroupement des vérifications d'activité des nœuds et transmetteurs du réseau.
- **Module Mekanism** — Temporisation des scans d'aspiration des câbles inactifs, des scans d'émission des réseaux et des recalculs de chemin à vide des Logistical Transporters, plus un rendu client sûr et optionnel des Logistical Transporters colorés avec une garde sur le cache de modèles.
- **Variantes de jar** — `all`, `botany`, `refinedstorage` et `mekanism` ; la commande du menu d'administration suit la variante choisie.
- **Vérifications structurelles des Mixins** — Une cible modifiée ne saute que le Mixin concerné au lieu de faire planter tout le jar.

## [0.1.0] - 2026-04-25

### Added
